▎ 范式转变

GPT-3 让人们意识到：不用 fine-tuning，仅靠「示例 + 指令」就能让模型完成新任务。

这意味着工程化 LLM 应用的门槛被大幅拉低——从此「写 Prompt」成为一项核心技能。

关键里程碑：
→ 2020 GPT-3 论文首次系统描述 In-context Learning
→ 2021 Brown et al. 提出 Few-shot Prompting
→ 2022 ChatGPT 开启大众 Prompt 时代

/04 · PROMPT · TECHNIQUES
STAGE 01 · 核心技巧

Prompt Engineering 核心技巧

从「Few-shot」到「让模型自己思考」

TECH 01

Few-shot Prompting

通过若干「示例对」教会模型任务模式。比 Zero-shot 更稳定，几乎是 Prompt 工程的起点。

TECH 02

Chain-of-Thought (CoT)

让模型「Let's think step by step」。在算术、推理任务上带来 10x 量级的提升。

TECH 03

ReAct

Reason + Act 交替：思考 → 调工具 → 观察 → 再思考。打通 LLM 与工具的雏形。

TECH 04

Self-Consistency

采样多条推理路径后投票。少数服从多数，把 CoT 的不稳定性变成稳定性。

TECH 05

Tree of Thoughts

把单链推理拓展成树状探索，支持回溯与多分支评估。处理更复杂决策问题。

TECH 06

Automatic Prompt Eng.

让 LLM 自己生成并挑选最优 Prompt。从手写走向自动化的转折。

「我们花了两年时间惊叹于 Prompt 的魔力，直到意识到——
真正决定模型表现的，是 上下文里到底有什么。」

/05 · PROMPT · LIMITS
STAGE 01 · 局限性

Prompt 解决不了的问题

五条边界，把 Prompt Engineering 逼向下一阶段

⚠

上下文窗口受限

无论 4K、32K 还是 200K，Prompt 始终存在容量上限。一旦超出，关键信息被截断，模型表现断崖式下降。

⌛

知识截止与时效性

训练数据有终点。问"昨天发生了什么"几乎注定得不到准确答案，Prompt 写得再巧妙也无济于事。

∅

幻觉与编造

当模型不知道时，会一本正经地胡说。Prompt 只能缓解，无法根除——知识缺口不能靠措辞修补。

◇

缺乏持续记忆

每次对话都是孤岛，模型没有真正的"记忆"。跨会话、跨任务的上下文全部依赖手工拼装。

⇡

难以处理复杂任务

多步、长链路、需要外部交互的任务——纯 Prompt 越写越长，最终变得不可维护。

↯

无法访问真实世界

Prompt 只能调动模型内部知识，无法读取文件、调 API、操作浏览器——这正是 Tool Use 要解决的问题。

结论 · 当任务的瓶颈从「怎么说」转移到「说的时候能用到什么」——
我们就不得不进入下一个范式。

/06 · CONTEXT · WHY
STAGE 02 · 为什么 Context 决定一切

Context is All You Need

2025 年，业界不约而同提出一个口号

"Context Engineering is the new Prompt Engineering."

— Andrej Karpathy · 2025.07

"I hate the term 'prompt engineering'. It's just an unfortunate name."

— Andrej Karpathy · 2025.07

业界共识正在形成：

LLM 本质上是一个「上下文计算机器」——给它什么上下文，它就只能产出对应水平的答案。

Prompt 只是上下文的一种形式。真正的杠杆在于：
检索 / 记忆 / 工具 / 多模态 / 反馈—— 所有能往 context 里"装东西"的技术。

/07 · CONTEXT · KEY TECH
STAGE 02 · 关键技术

RAG · Memory · Tool Use

三把武器，把上下文真正"装满"

◉ 01 · RETRIEVAL

RAG

检索增强生成

  • Vector Database
    Embedding 索引 + 相似度召回
  • Hybrid Search
    关键词 + 向量混合检索
  • Re-ranking
    粗排 → 精排提升 Top-K 质量
  • GraphRAG
    知识图谱增强全局推理
  • Agentic RAG
    Agent 主动决定何时检索什么
◉ 02 · MEMORY

Memory

记忆系统

  • Short-term
    当前会话与滑动窗口
  • Long-term
    向量库 + 摘要压缩
  • Episodic
    事件级回忆 · 行为回放
  • Semantic
    概念级知识沉淀
  • Procedural
    技能与流程 · 可复用
◉ 03 · TOOL USE

Tool Use

工具调用

  • Function Calling
    结构化 JSON 调用外部函数
  • Code Execution
    沙箱里跑代码 · 真实计算
  • Browser Use
    浏览、操作、点击、表单
  • MCP 协议
    Model Context Protocol · 工具标准化
  • Tool Discovery
    运行时发现与组合工具

把这三个轴组合起来，就得到了 RAG + Memory + Action 的最小 Agent 闭环——
也正是 Harness Engineering 真正开始工作的起点。

/10 · SUMMARY
RECAP · 三阶段总结

三阶段，一条递进曲线

每个阶段都没有消失，而是被新的层包含

2020 · STAGE 01
Prompt Eng.

把人能「写出来的话」当作模型的最大杠杆。

代表技巧：CoT / ReAct / ToT

核心局限：无记忆 / 无外部世界 / 不可持续

↓ 推动 Prompt → Context
2023 · STAGE 02
Context Eng.

把"模型能看见的东西"全部工程化，变成可装配的能力。

关键模块：RAG / Memory / Tool Use

核心协议：MCP / ACP / Function Calling

↓ 推动 Context → Harness
2025 · STAGE 03
Harness Eng.

把 LLM 看作 LPU，组装一套可持续运行的 Agent 运行时。

代表产品：AutoGPT / Devin / Claude Code

核心议题：可靠性 / 可观测 / 可控性

→ Agentic Future

▎ 不变的主题

  • 人不是去"控制"模型，而是去"装配"模型的环境
  • 每一层范式的升级，都让更多任务从"演示"走到"生产"
  • 可靠性 > 聪明程度

▎ 未来方向

  • Agent Harness 标准化（协议 / Runtime）
  • 多 Agent 协作（角色 / 协议 / 经济）
  • 从云端 Agent 到本地 / 端侧 Agent
  • 可观测、可审计、可回放
